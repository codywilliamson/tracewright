# Tracewright v0.1 — Design

**Date:** 2026-08-11
**Status:** Reviewed — implementation-ready (design grilling 2026-08-11 → 2026-08-12; decisions D-014…D-024)
**Constraint:** Everything here is designed against verified Claude Code hook data
(see [`../notes/2026-08-11-claude-code-hook-surface.md`](../notes/2026-08-11-claude-code-hook-surface.md))
and the decisions in [`../decisions.md`](../decisions.md). No imagined lifecycle
abstractions.

## Goal

> Install Tracewright into the Tracewright repository and produce a trustworthy
> timeline correlating Claude Code hook activity with Git post-commit activity,
> while explicitly showing unknown or unattributed activity instead of hiding it.

v0.1 does not answer "why." It proves *what happened*: what Claude Code hooks
reported, what Git reported, which events correlate, which don't, what evidence
kind each record has, and which raw source event supports every timeline line.

**Invariant (D-019): Tracewright preserves uncertainty rather than normalizing
it away.** Nullable correlation, carrier vs claim, unattributed/unanchored
rendering, best-effort ordering, and asserted-by-default raw ingress are all the
same rule — where the evidence is uncertain, the ledger says so instead of
guessing.

## Scope

Five pieces (D-005), nothing else:

1. **Event store** — append-only SQLite
2. **`tracewright emit`** — the single ingest path
3. **Claude Code adapter** — hook payloads → events
4. **Git post-commit adapter** — commits → events
5. **`tracewright timeline`** (+ `tracewright show`) — read it back

Out of scope (listed once, not shaped): `ask`, context packets, decision
extraction, memory promotion, LLM derivation, semantic search, embeddings, Codex
adapter, daemon, web UI, Durable Task, NativeAOT, multi-repo project model
(beyond a nullable column), discrepancy engine beyond unattributed rendering,
`init`/`doctor` (manual onboarding for now).

## 1. Event envelope

One event = one row. The envelope classifies and correlates; the payload
preserves the source verbatim.

| Field | Type | Null | Meaning |
|---|---|---|---|
| `event_id` | ULID | no | Primary key; lexically sortable by creation time |
| `occurred_at` | ISO-8601 UTC | no | When it happened, per the source |
| `received_at` | ISO-8601 UTC | no | When Tracewright persisted it |
| `kind` | text | no | `observed` \| `asserted` \| `derived` (see §3) |
| `event_type` | text | no | Tracewright dotted type, e.g. `claude.tool.failed` |
| `emitter_name` | text | no | `claude-code` \| `git` \| `manual` |
| `emitter_version` | text | yes | Source system version when discoverable (e.g. CC `2.1.227`) |
| `adapter_version` | text | no | Tracewright adapter version that translated this event |
| `original_event` | text | yes | Source-native name, e.g. `PostToolUseFailure`, `post-commit` |
| `session_id` | text | yes | Emitter's session id |
| `prompt_id` | text | yes | Claude Code ≥ 2.1.196 only |
| `tool_use_id` | text | yes | Joins hook events to transcript `tool_use` blocks |
| `agent_id` | text | yes | Present when a hook fires inside a subagent |
| `parent_id` | text | yes | Reserved: link to a causing/parent event (unused by v0.1 adapters) |
| `repository_id` | text | yes | From `.tracewright/repo.id` (§6) |
| `worktree_id` | text | yes | Worktree root path — correlation hint, not identity |
| `raw_ref` | JSON | yes | Evidence pointer, e.g. `{"transcript_path": "..."}` — pointer, never a copy |
| `payload` | JSON | no | Full source payload, verbatim |

Rules:

- **Every correlation field is nullable.** Adapters record what the source
  provides and never invent values (D-003; hook fields vary by CC version).
- **Unknown source events are normal.** An unrecognized `hook_event_name` maps to
  `claude.hook.unknown` with `original_event` preserved and the payload verbatim.
  Version drift must not lose evidence.
- **Events are immutable.** No update or delete code path exists. Corrections are
  future events referencing prior `event_id`s.
- **Dual timestamps, best-effort order (D-016).** `occurred_at` is stamped as the
  adapter's first action on invocation, before parsing or DB work; `received_at`
  is when Tracewright persisted. Async hooks may persist out of order; rendering
  is best-effort chronological, with no corrective heuristics unless the ledger
  itself shows real inversions.

## 2. SQLite schema

Location: `~/.tracewright/tracewright.db`. Never inside a repository (D-004).

```sql
CREATE TABLE meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);  -- schema_version, created_at

CREATE TABLE events (
  event_id        TEXT PRIMARY KEY,
  occurred_at     TEXT NOT NULL,
  received_at     TEXT NOT NULL,
  kind            TEXT NOT NULL CHECK (kind IN ('observed','asserted','derived')),
  event_type      TEXT NOT NULL,
  emitter_name    TEXT NOT NULL,
  emitter_version TEXT,
  adapter_version TEXT NOT NULL,
  original_event  TEXT,
  session_id      TEXT,
  prompt_id       TEXT,
  tool_use_id     TEXT,
  agent_id        TEXT,
  parent_id       TEXT,
  repository_id   TEXT,
  worktree_id     TEXT,
  raw_ref         TEXT,              -- JSON
  payload         TEXT NOT NULL      -- JSON
);

CREATE INDEX ix_events_occurred ON events (occurred_at);
CREATE INDEX ix_events_session  ON events (session_id, occurred_at);
CREATE INDEX ix_events_repo     ON events (repository_id, occurred_at);
CREATE INDEX ix_events_type     ON events (event_type);
```

- `PRAGMA journal_mode=WAL` + `busy_timeout` — parallel async hooks mean
  concurrent writers; WAL handles it without a daemon or queue.
- Payload stays JSON. Fields earn indexed columns only when a real query needs
  them (D-006). No payload field is promoted in v0.1.
- Migrations: numbered scripts keyed off `meta.schema_version`. Boring on purpose.
- **Lazy bootstrap (D-024).** Any write path creates `~/.tracewright/`, the
  database, and the schema on first use — adapters run from hooks that must
  never fail and cannot depend on a setup step. Read commands on a missing or
  empty store report "no events recorded" and exit 0. Migration check on every
  open.

## 3. Evidence kind semantics

From D-002 and D-012:

- **`observed`** — the record was emitted by a deterministic mechanism with no
  model or human claim required in the reporting chain.
- **`asserted`** — the record's informational content originates from an explicit
  human or model claim.
- **`derived`** — Tracewright produced it from other events, linking to them.

`kind` classifies **why the record exists**, not the truth of every payload
field. Observed events routinely carry assertion material in their payloads
(`TaskCompleted(result: success)`, `last_assistant_message`, commit messages).
Extracting that material into asserted events is derivation — out of scope for
v0.1, but the payloads are preserved so it's possible later.

Practical consequences for v0.1:

- Both adapters emit **`observed` only**.
- `asserted` enters solely through `tracewright emit raw` (a human deliberately
  recording a note/decision as an event). It is `emit raw`'s default kind;
  `observed` requires an explicit `--kind observed`, and `derived` is rejected
  at the raw boundary (D-014, D-020).
- No `derived` events are produced. The kind is reserved and schema-valid;
  `parent_id` is where single-input derivation will link (multi-input links get a
  table when derivation actually exists).
- `Unknown` is not a kind. It is a query/projection result (D-010: the timeline
  represents absence; it does not store it).

## 4. Correlation model

Adopt the verified native spine, all nullable:

```
session_id  →  prompt_id  →  tool_use_id  →  agent_id
```

- Claude events carry whatever subset their CC version provides.
- Git events carry `repository_id` (+ `worktree_id`) and normally **no** session
  correlation.
- Correlation is established only by **shared identifiers**, never by heuristics.
  Time-adjacency guessing ("this commit happened right after that Bash
  `git commit` tool call") is a future *derived* finding, not a v0.1 timeline
  behavior.
- `worktree_id` is the worktree root path — a correlation hint. Repository
  identity comes from `.tracewright/repo.id`, which resolves identically in every
  worktree because each worktree checks out its own copy of the file.

## 5. Claude Code adapter

Invocation: hooks call `tracewright emit claude`; the full hook JSON arrives on
stdin. Exec form, `async: true` — capture never blocks the agent loop and
cross-platform quoting never happens.

Hook registration (project `.claude/settings.json`, committed — the integration
travels with the repo; graceful behavior when `tracewright` is not on PATH is an
`init`-phase concern we accept during dogfooding):

```json
{
  "hooks": {
    "SessionStart":       [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "UserPromptSubmit":   [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "PreToolUse":         [{ "matcher": "*", "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "PostToolUse":        [{ "matcher": "*", "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "PostToolUseFailure": [{ "matcher": "*", "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "Stop":               [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "SubagentStart":      [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "SubagentStop":       [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "TaskCreated":        [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "TaskCompleted":      [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "SessionEnd":         [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "PreCompact":         [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "PostCompact":        [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "WorktreeCreate":     [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }],
    "WorktreeRemove":     [{ "hooks": [{ "type": "command", "command": "tracewright", "args": ["emit", "claude"], "async": true }] }]
  }
}
```

Mapping (`hook_event_name` → `event_type`, all `kind=observed`):

| Hook | `event_type` | Summary source in payload |
|---|---|---|
| `SessionStart` | `claude.session.started` | `source` (startup/resume/clear/compact/fork) |
| `UserPromptSubmit` | `claude.prompt.submitted` | `user_input` (truncated for display, stored whole) |
| `PreToolUse` | `claude.tool.started` | `tool_name` + `tool_input` summary |
| `PostToolUse` | `claude.tool.succeeded` | `tool_name` + `tool_input` summary |
| `PostToolUseFailure` | `claude.tool.failed` | `tool_name` + `tool_input` summary |
| `Stop` | `claude.turn.completed` | `stop_reason`; `last_assistant_message` preserved in payload |
| `SubagentStart` | `claude.agent.started` | `agent_type` |
| `SubagentStop` | `claude.agent.completed` | `agent_type` |
| `TaskCreated` | `claude.task.created` | `task_name` |
| `TaskCompleted` | `claude.task.completed` | `task_name` + `result` (agent's claim — payload, not certified) |
| `SessionEnd` | `claude.session.ended` | `reason` |
| `PreCompact` | `claude.context.compacting` | marks imminent context loss — carries what is about to disappear |
| `PostCompact` | `claude.context.compacted` | marks context loss |
| `WorktreeCreate` / `WorktreeRemove` | `claude.worktree.created` / `.removed` | path |
| *anything else* | `claude.hook.unknown` | `original_event` preserved |

Envelope population: `session_id`, `prompt_id`, `tool_use_id`, `agent_id` from
the payload when present; `occurred_at` = stamped as the adapter's first action on
invocation, before parsing or DB work (D-016), unless the payload carries a
source timestamp; `raw_ref` = `{"transcript_path": ...}` (pointer only — the
transcript file lags, never read it synchronously); `emitter_version` = CC
version if discoverable, else null; `repository_id` resolved by walking up from
`cwd` to find `.tracewright/repo.id`.

Verified limitation, restated so nobody re-promises it: **no structured exit
codes** (success/failure binary via which hook fired) and **no structured agent
assertions** (they live inside observed payloads).

## 6. Git post-commit adapter

Manual v0.1 installation: a `post-commit` script in the repo's active hooks
location invoking `tracewright emit git post-commit`. The general interop
strategy (`core.hooksPath` vs chaining — must coexist with commit-guard) remains
open and is an `init`-phase problem; for dogfooding this repo we install
directly (verified 2026-08-11: this repo sets no `core.hooksPath` and its hooks
dir holds only samples).

The git adapter is the one place Tracewright observes semi-directly — it queries
git itself rather than trusting a relayed payload:

- `event_type`: `git.commit`, `kind: observed`, `emitter_name: git`
- Payload gathered at hook time: commit sha, parent shas, branch, author
  name/email, author/committer timestamps, subject line, `--name-status` file
  list. (The commit *message* is asserted narrative inside an observed event —
  carrier vs claim.) `emitter_version` = `git --version` at hook time.
- **One firing, one event (D-023).** `post-commit` fires per commit object
  created — amends, cherry-picks, and rebases produce multiple `git.commit`
  events with distinct shas. No dedup (dedup is derivation by stealth); rewrite
  lineage (`post-rewrite`) is deferred, revisit if amends prove common.
- `occurred_at` = committer timestamp; `repository_id` from `.tracewright/repo.id`;
  `worktree_id` = worktree root.
- **May** additionally record `CLAUDE`-prefixed environment variables present in
  the hook process into `payload.env_hints` — mechanically inherited when the
  commit ran inside a Claude Code Bash tool, hence observed. Verified 2026-08-13
  during dogfooding: `CLAUDE_CODE_SESSION_ID` is present at post-commit time and
  matches the live session. Using it for attribution is future *derived*
  correlation (D-013); v0.1 timeline attribution does not depend on it.
- The hook **always exits 0**. A broken Tracewright must never break a commit.

Repository identity: `.tracewright/repo.id` is an **opaque unique string**
(D-022) — identity needs uniqueness and stability, not sortability. Created by
hand during manual onboarding (`uuidgen > .tracewright/repo.id`) and committed;
no generator command, and never auto-created by a hook (a git hook must not
write into the working tree as a side effect). Clones and worktrees sharing the
id is correct behavior (D-004 model).

## 7. Timeline projection

`tracewright timeline` renders events chronologically. It is a read-side
projection — it stores nothing, derives nothing persistent.

```
tracewright timeline [--repo [<id>]] [--session <id>] [--since <t>] [--until <t>]
                     [--type <glob>] [--kind <k>]
```

Rendering rules:

1. Order by `occurred_at`, tiebreak `received_at`, then `event_id`.
2. Each line: local time · `KIND` · `event_type` · per-type summary ·
   correlation tag · short `event_id`. Every line is traceable: the short id
   feeds `tracewright show`.
3. **Chronology wins (D-017).** Grouping is presentation metadata, never
   permission to reorder: session/repository headers reprint whenever the
   stream switches, so interleaved sessions render as interleaved — concurrency
   is evidence. Subagent events render indented with `agent_type`.
4. Content fields (prompts, messages, commands) are truncated for display —
   never truncated in storage.
5. Default window: `--since 24h` when no filter is given. `--since`/`--until`
   accept relative (`24h`, `7d`) and ISO-8601 forms.
6. **Default view is the whole ledger (D-021)** — all repositories plus
   unanchored events. Bare `--repo` narrows to the repository resolved by
   walking up from cwd (the same resolution adapters use); `--repo <id>` is
   explicit. No silent auto-scoping.

Example (honest — matches what capture actually provides):

```
session fe9f21f8 (claude-code)
  10:41:02  OBSERVED  claude.session.started    source=startup            [01J9…4F]
  10:41:18  OBSERVED  claude.prompt.submitted   "implement event persis…" [01J9…52]
  10:43:51  OBSERVED  claude.tool.failed        Bash: dotnet test         [01J9…6A]
  10:45:22  OBSERVED  claude.tool.succeeded     Bash: dotnet test         [01J9…71]
  10:45:40  OBSERVED  claude.turn.completed     stop_reason=end_turn      [01J9…7C]

repository tracewright
  10:46:01  OBSERVED  git.commit                83bd41a "feat: event st…"
                      correlation: none — unattributed                    [01J9…80]
```

## 8. Unattributed and unknown states

D-010, made concrete:

- A `git.commit` with no shared identifier linking it to any session renders
  **`correlation: none — unattributed`**. This is truthful evidence, not a
  failure state.
- Claude events with no `repository_id` (work outside any onboarded repo) render
  under their session with no repo tag — visibly unanchored.
- The timeline never interleaves unattributed activity as if explained, and never
  omits it. Filters like `--session` exclude by correlation, and say so in a
  trailing note when unattributed events exist in the same time window
  (`n unattributed events in this window — run without --session to see them`).
- These states are the free v0.1 discrepancy surface: commits with no agent
  correlation, agent activity with no commit, tool failures followed by commits.
  No engine needed — the rendering *is* the detector.

## 9. Raw payload preservation and privacy assumptions

**Trust model (D-014):** the trust boundary is the local machine and its user.
Tracewright is not tamper-proof and does not pretend to be — anything on the
machine can pipe JSON at `emit`. `kind` classifies **provenance semantics, not
cryptographic trustworthiness**; defaults encode the epistemic model (asserted
by default on raw ingress) and enforcement is not attempted.

- Payloads are stored **verbatim** in the local store: prompts, commands, tool
  output, messages. This is the point of an evidence ledger.
- The database lives in `~/.tracewright/`, is never placed inside a repository,
  and nothing in v0.1 writes evidence anywhere else. The repo's `.gitignore`
  excludes `*.db` as a second line of defense.
- No redaction machinery in v0.1 (deferred, not forgotten — D-004 boundary:
  nothing auto-promotes to anything committed).
- `tracewright emit` never logs its own environment. Only the bounded
  `CLAUDE`-prefixed capture in §6 touches env at all.
- Failure handling: adapters log errors to `~/.tracewright/logs/` and exit 0
  from hook contexts. Capture is best-effort; the user's workflow is sacred.

## 10. CLI

```
tracewright emit claude              # hook JSON on stdin → event
tracewright emit git post-commit    # queries git, emits git.commit
tracewright emit raw                # full envelope JSON on stdin (kind/type caller-supplied)
tracewright timeline [filters]      # chronological projection
tracewright show <event-id>         # full envelope + verbatim payload (id prefix ok)
```

`emit raw` is the universal ingress: every adapter internally produces the same
envelope this command accepts — and it is itself an adapter, **`tracewright.raw`**
(D-015). Tracewright always stamps `event_id`, `received_at`, and
`adapter_version`; caller-supplied values for those are **rejected, not silently
overwritten**. The caller supplies the rest:

- `kind` — default `asserted`; `observed` requires an explicit `--kind observed`;
  `derived` is rejected at this boundary (D-014, D-020)
- `event_type` — free-form by convention: adapters own `claude.*` and `git.*`,
  `tracewright.*` is reserved for future derived events, manual events use
  unprefixed dotted names (`note.recorded`, `decision.recorded`)
- `emitter_name` (default `manual`), `emitter_version`, correlation ids,
  `occurred_at` (default: invocation time), `raw_ref`, `payload`

A human recording a note today uses the same path a future Codex adapter will.
Historical replay/import, if ever needed, is a separate future ingest mode — not
a loosening of `emit raw`.

`tracewright show` resolves id prefixes; an ambiguous prefix errors and lists the
matches.

The binary answers to two names: `tracewright` and the alias **`twr`**. Committed
configuration (hooks, settings) always uses the canonical `tracewright`; `twr`
exists for humans at a terminal.
No other commands. `init` and `doctor` arrive only after these five prove out.

## Implementation shape

- **Stack:** C# / .NET 10 — `System.CommandLine`, `Spectre.Console` (timeline
  rendering), `Microsoft.Data.Sqlite` (raw SQL; one table does not need an ORM),
  xUnit. Central package management, nullable + implicit usings, matching
  `worktree-commander` conventions. Assembly name `tracewright`; `twr` ships as an
  alias (symlink/shim on PATH, cmd shim on Windows).
- **Layout:** `src/Tracewright.Cli` (parsing + rendering), `src/Tracewright.Core`
  (envelope, store, adapters), `tests/Tracewright.Tests`.
- **No NativeAOT, no daemon, no queue** (D-007). Async hooks make CLI startup
  latency invisible to the agent; the git hook path is synchronous but trivial.
  Measure before optimizing; HTTP hooks are the ready-made daemon seam if ever
  needed.

## Manual onboarding (v0.1, this repo)

1. Build; put `tracewright` (and the `twr` alias) on PATH.
2. `uuidgen > .tracewright/repo.id`; commit it.
3. Commit the hook block into `.claude/settings.json` (§5).
4. Install the post-commit hook (§6).
5. Develop normally in a Claude Code session; commit something.
6. `tracewright timeline`.

## Acceptance criteria

1. A real working session produces `claude.session.started`, prompt, tool
   succeeded/failed, and turn-completed events with correct correlation ids.
2. A commit made during that session produces a `git.commit` event; a commit made
   outside any session (e.g. from a bare terminal) renders **unattributed**.
3. Every timeline line resolves via `tracewright show` to the verbatim source
   payload that supports it.
4. All adapter events carry `kind=observed`; a manually emitted note carries
   `kind=asserted`.
5. An unrecognized hook event is captured as `claude.hook.unknown`, not dropped.
6. Capture adds no perceptible latency to the agent loop and can never fail a
   git commit or block a session.

No structured exit codes. No structured agent assertions. No "why" questions.

- Transcript record-level citation (`raw_ref.record_uuid`) — needs a
  lag-tolerant resolution strategy; v0.1 stores the file pointer only
- `env_hints` captures `CLAUDE_CODE_MESSAGING_TOKEN` among the `CLAUDE*` vars —
  local-only per §9, but flag it for the redaction backlog
